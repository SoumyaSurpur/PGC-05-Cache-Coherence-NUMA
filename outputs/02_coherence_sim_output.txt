Key Architectural Observations & Analytical Points:
1. False Sharing Catastrophe in Adjacent Layout:
   - When counters x and y share cache line A, 4000 memory operations generate
     nearly 4000 bus transactions (3999-4000), 1999 invalidations, and 1999 flushes.
   - Every single write by Core 0 forces Core 1's copy into Invalid ('I') state,
     and vice-versa, causing extreme bus contention and cache thrashing.

2. Padded Layout (64-byte Alignment) Eliminates Invalidation:
   - When x and y are padded onto separate cache lines (Lines A and B), total
     bus transactions collapse from ~4000 down to just 2 to 4!
   - Invalidations drop to exactly ZERO. Once loaded, each core maintains its
     private line in Modified ('M') state and writes locally with zero bus overhead.

3. Protocol Differences (MSI vs MESI vs MOESI):
   - MESI saves 1 bus transaction on the very first private write via the Exclusive (E)
     state, performing a "Silent E -> M" transition without broadcasting BusUpgr.
   - MOESI completely eliminates memory writebacks (0 writebacks vs 1999 in MSI/MESI)!
     Instead, the Owned (O) state enables dirty cache-to-cache (C2C) transfers (1999 C2C),
     drastically reducing high-latency main memory traffic.
